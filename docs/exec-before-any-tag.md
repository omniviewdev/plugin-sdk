# Before any tag that ships `exec.v2`

[Docs home](README.md) · [Exec: run commands in a target](exec.md)

This page keeps, verbatim and not edited, the conditions that the independent review of head `ed6f26f8445c2e756de5506882c3927e9f228b47` of the exec v2 contract (`proto/exec/v2/exec.proto`, `pkg/v1/exec`), by `ReviewSdk87`, sets before **any** tag that ships `exec.v2`: a stable tag cut from `main` ships the contract for good. The file and line references (`exec.proto:1268`, `docs/exec.md:121`, `limits.go:102`, ...) are to that head, not to the tree you are reading, and the text of the conditions is a record of the review: it is not edited. What has been met since is recorded only in [Status since the review](#status-since-the-review), at the end of the page, item by item, with the tests that hold it.

- **C3, process.** `proto-breaking` baselines against the latest *stable* tag (`.github/workflows/native-exec.yml:96-106`), v0.22.0, which has no `exec.v2`, so it guards nothing until a stable release carries the file; and **any stable tag cut from main after this merge ships `exec.v2` for good** (a bug-fix tag would do it). ### (B) The tag gate: what must change before a tag

#### B1. Shape decisions. 1 to 6 close the gate; 7 to 12 are decide-and-record, each with an additive path

1. **Narrowing** (blocker 4; the open follow-up). Decide: (i) declare selection-determined modes statically (`Choice` carries a narrower `Capabilities`, applied by the SDK at admission): `Opened` is then accurate, the picker can show "attach: no exit status, survives a host restart" before opening (the `mode` option of `docs/exec.md:167` shows nothing about it), and the fields that act at admission or when the pipes are wired (`tty`, `env`, `cwd`, `initial_size`, `stall`) can follow it; `Started` keeps only what is learned at run time. (ii) The SDK sends a `Started` (the author's, or one made from the bound) before the first `Output`, so no output is delivered under provisional capabilities; the illustration's gate disappears. (iii) Say that a new session's `Opened` capabilities are provisional until then. (iv) The cross-field rule the PR lists as open: narrowing `tty` to false empties `integration`. (v) Mutating `Proc.Capabilities` is inert today (only a reported `SessionFacts.Capabilities` counts): observe it or make it read-only.
2. **End invariants** (C1) and the `Lost` + `remote_may_survive=false` contradiction (a decoder rule).
3. **A stream that ended with no status** (SHOULD 8). `Exited{code, TRANSPORT}` exists and is unambiguous for a consumer that reads `source` (an unspecified source is never PROCESS; `ExitCode` on an `ExitReportNone` target is downgraded to TRANSPORT with a violation and survival absent: ran). The guide swapped the risk and did not remove it: `docs/exec.md:223-226` and the tested illustration return `ExitLost(LostNoStatus)` for every `err == nil`, and client-go's nil is also what a **Success** status looks like (the comment there says so), so every successful Kubernetes exec would end "connection lost, may still be running" and an agent `run` could never return success from a pod. The author keeps `Exited{TRANSPORT}` for "exactly the transport that relays a code of its own" (answer to 4661646443). I could not find such a transport in the prior-art table (`T-terminal-prior-art.md:364`): Kubernetes exec relays the process's own status on the error channel, attach relays none, docker `ExecInspect` and ssh `exit-status` the process's own; the codes that are the runtime's or the client's (docker's 126/127/128 for a start failure, OpenSSH's 255 for a dead connection) are, by this contract's own rules, `Failed` (start) and `Lost`, not exit codes. So today the only producer of `ExitTransport(n)` is an author inventing `n` (my reading). Decide with K2's real executor: if it can read the status channel (the guide says a plugin can), PROCESS for a Success status and `Lost` for an empty channel, and delete `EXIT_SOURCE_TRANSPORT` and `ExitTransport`; if not, add the no-code arm ("closed cleanly, status not reported") and delete them as well. A code on a no-status end is the one shape I would not tag.
4. **Values nobody can deliver:** `OUTCOME_CANCELLED`, `CLOSED_BY_RUN_TIMEOUT`, `CLOSED_BY_CANCELLED` (blocker 1c), and `CLOSED_BY_IDLE_TIMEOUT` ("idle for longer than its bound", `:1131`), for which no message has a field to set the bound (`SessionLimits` has seven fields, none of them an idle timeout). Define who produces them, or delete them now (free now, permanent after).
5. **Redundant fields that can disagree:** `start_observed` vs `Failed.stage`; `OutputAccount.truncated` vs `dropped_bytes` and `completeness` (`:1442,1451`, SHOULD 13). Drop one of each pair, or ship the decoder that rejects the disagreement with the first consumer.
6. **Consumer readers.** The raw getters flatten every `optional` the contract relies on and keep an unknown enum number. Ship the readers (an absent fact is unknown; `remote_may_survive` absent reads "may"; an unknown enum value reads UNSPECIFIED) with the first host consumer (H1a-1 reads `Describe` now). This is what the deleted Go mirror did.
7. **`OpenRequest.kind`** (the `oneof` at `:645`) to two optional fields (wire-identical) so that "both present" is refusable (the author's answer to 4661646400: decided at X3a, before any tag: agreed).
8. **Refusal encoding** (SHOULD 7): a typed message under `Status.details` or the `ErrorInfo.metadata` strings; one encoding, before H1a-1's decoder hardens (`Options` refusals already use the metadata).
9. **`Session`/`Run` declaration** (SHOULD 4): a target with neither registers and serves only `Options` (now documented, `docs/exec.md:47,87`; still silent in code) and `Exec` is required even for an Options-only target.
10. **Ownership and sizes** (SHOULD 14, 15, 16): `ListSessions`, `ReadOutput` and `EndSession` carry no route (`:1338-1363`); one bound policy (refuse or clamp); the largest `Output` frame and `ReadOutput` and `ListSessions` response.
11. **`Exit` default:** `SourceUnspecified` beside a code reads PROCESS; read it as the weakest (TRANSPORT + violation) so that `ExitCode(...)` is the only way to claim PROCESS; consider an opaque `Exit`.
12. **Vocabularies and the string guard:** `Choice` kinds, details and states (K1a); `TestAbsenceIsUnknown` to cover strings; `Mark.command_line` and `cwd` presence.

#### B5. The three threads answered with a reason

- **A `oneof` arm the decoder discards** (4661646400, `admission_v2.go`): acceptable. The decoder keeps only the last arm and the reflection walk cannot see an unknown field in the discarded one, so a frame carrying both arms reaches admission as the later arm alone: a malformed sender, not a downgrade, and nothing the reader does not understand is acted on. The wire-identical fix (two optional fields) is B1.7.
- **An `Exited` arm from the transport** (4661646443, `exit.go`): acceptable for the merge, not for the tag (B1.3). On the wire the source makes it unambiguous: an unspecified source is never PROCESS, `ExitCode` on a `NONE` target is downgraded to TRANSPORT with a violation and survival absent (ran), and `RunResult` carries `exit_source` beside `exit_code`. It is confusable only by a consumer that prints the code and drops the source, and only if the engine feeds the kind's capabilities (A).
- **A bare `Canceled` from a catalog provider** (4661646447, `plugin_server_v2.go`): acceptable. The author's reason: a provider that returns `context.Canceled` from a downstream operation of its own is misread as a retirement, that is a provider bug, and the lease ends on return so it cannot be told apart from outside. `Options` is a read and a retry is safe; the mutant that drops the caller-alive guard (R22) is killed.

#### B6. The open follow-up, 4661646396 (a write that arrives without `Started`)

Not a docs nit, and not a hole in the way the bot frames it. After the fix, the bot's only real reply says "One race remains: `awaitStream` checks `first.seen` and finds it open; a writer starts after; the deferred `first.release()` unblocks it without a `Started` report ... make the return path fail closed for writes that arrive without a `Started` report ... I am not marking the finding as addressed." **The SDK itself accepts output with no `Started`, by contract:** `Proc.Started` says a command that never calls it "is reported as started when its first output arrives", and the proto says its capabilities then "stay the kind's upper bound" (`:774`); the rig accepts it (ran: output, zero `Started` reports). So no illustration can make the SDK refuse that order, and the gate in the illustration protects an invariant the contract does not give. The real finding is blocker 4's: the contract lets output run under provisional capabilities and gives the author no way to be early, so every author with modes will re-implement that gate and get it wrong (the bot found one race, and after the fix another). The fix belongs in the SDK (B1.1 ii) and settles the thread; until then the illustration should not be the pattern the guide teaches (it also encodes the "nil is Lost" decision of B1.3).

#### B7. Guards and proof

- The Kubernetes compile proof against the real client-go, before the tag (B4).
- `proto-breaking` is trivial until the first stable release that carries the file; until then the reviewed golden is the only guard, and `-update` regenerates it (C3).
- Pin `defaultMaxDimension` and `maxTargets` to the numbers the guide prints (the two survivors).
- `Exit.end` must receive the session's effective set (A).

### Status since the review

This section is added to the record; the conditions above are as the review wrote them. It says, item by item, where each condition stands after the X3b change (the control frames, queries, signals and stdin EOF, the keepalive, and the findings of the Kubernetes proof) and the X3c change (the replay ring, attach, detach, the lease, the tombstone and the three session calls), which ship together, with the tests that show it (`go test ./pkg/v1/exec/... ./pkg/sdk/... ./pkg/utils/... ./examples/... ./proto/...`). **Closed** means the condition is met and a test holds it, **decided** that the answer is written and the code follows it, **open** that nothing in this change moves it. The Kubernetes evidence is the proof of a Pod provider on this contract, `SDK2-K-proof` (branch `wip/spike/exec-v2-provider` of the Kubernetes plugin, a37f0d05, kind v1.34.0 on containerd 2.1.3).

**The conditions, one by one.**

- **C3, process: open.** This change cuts no tag and edits no workflow. `proto-breaking` still baselines against the latest stable tag, which carries no `proto/exec/v2` (v0.22.1), so it guards nothing until a stable release carries the file, and the reviewed golden (`proto/exec/v2/exec.contract.golden`, held by `TestContractMatchesItsReviewedGolden`) is the only guard of the wire. The condition stands: cut no stable tag from `main` before the gate. The change to the wire is one additive field, `Choice.no_program` (8), and the comments of `Exited` and `EXIT_SOURCE_TRANSPORT`.
- **B1.1, narrowing: (i) and (ii) closed, (iii) moot, (iv) and (v) open.** (i) A `Choice` declares the mode of a session in `Choice.Capabilities` (wire field `Choice.capabilities`); the host reads it with the options before it opens anything, and the SDK opens the session with the kind's bound narrowed by the choice that each option takes in the selection (the default choice of an option the selection omits), so `Opened` is accurate: `TestOpenedCapabilitiesAreTheKindNarrowedByTheChoicesTheSelectionNames`, `TestAChoiceCannotOpenASessionWiderThanItsKind`, `TestAChoiceWiderThanItsKindIsServedClampedAndTheAuthorIsToldInTheLog`, `TestAChoiceCarriesItsCapabilitiesOverTheWireAndNilStaysAbsent`, conformance case 26, and the proof (`Opened` carried exactly the two modes of the Pod: `HostRestart` none for an exec, `ExitReport` none for an attach). What follows a mode is what the SDK enforces on the session after admission (resize, stdin EOF, signals, the fact modes, stall, `Kill` and `ExitReport`); what does not is the request: admission still holds `tty`, `env`, `cwd` and `initial_size` to the kind's bound, so a mode that narrows one of them narrows what `Opened` says and refuses nothing. (ii) The host never receives output ahead of the session's `Started` (B6). (iii) `Opened` is not provisional: it carries the mode, and `Started` only narrows what is learned at run time. (iv) The cross-field rule (narrowing `TTY` empties `Integration`) is not written, and nothing depends on it while the SDK serves no integration. (v) `Proc.Capabilities` is a deep copy: changing it changes nothing, and only a `SessionFacts.Capabilities` reported with `Started` counts (its documentation says so); it is neither observed nor read-only.
- **B1.2, end invariants: closed; the decoder rule is open.** A session has one end and at most one `Ended`, every stream that can still receive frames ends with exactly one of `Ended` or `Detached`, and the end of a session with no stream is the tombstone's. Tests: `TestEveryStreamOfASessionEndsWithExactlyOneOfEndedOrDetachedAndTheSessionHasOneEnded`, `TestEveryPairOfOperationsOnASessionLeavesItInALegalStateWithAtMostOneEnd`, `TestCloseAndDetachInEitherOrderLeaveTheSessionInTheSamePlace`, `TestBlocker3SupersededIsADetachNotAnEnd`, conformance cases 9, 25 and P5, and the stress harness, which holds them at rest under load. The SDK never writes a `Lost` end with `remote_may_survive` false: `Lost` is always true (`TestEveryEndOfASessionThatTheSDKMakesSaysWhetherTheProcessMaySurviveByTheTargetsKill`). A decoder that rejects the pair in a message from another producer is a host reader's (B1.6).
- **B1.3, a stream that ended with no status: decided and closed.** The decision: Kubernetes' `Success` is "the transport reported a normal end", not the process's exit 0, because after a kubelet or containerd restart the API server sends `Success` for a command that did not exit 0 (8 of 8 sessions through the tap; the provider that read the channel returned `Exited{0, PROCESS}` for 4 of 4). `Exited{0, TRANSPORT}` stays and is not vestigial: it is the arm for that `Success`, with the start observed and `remote_may_survive` absent; a non-zero status is `PROCESS`; an empty channel or a break is `Lost`. Closed by `exec.ExitOfStreamError` (nil to `ExitTransport(0)`, an `ExitStatus()` or `ExitCode()` error to `ExitCode(n)`, anything else to the author) and `exectest.CodeExitError`, the guide's section "Ending a command over a client library" and its illustration, and the proto comments of `Exited` and `EXIT_SOURCE_TRANSPORT` (comments only: `buf generate` leaves no diff and `buf breaking` against the base is clean). Tests: `TestExitOfStreamError*`, `TestCodeExitErrorHasTheShapeAndTheMessageOfClientGosCodeExitError`, `TestAQuietCommandThatEndedNormallyIsExitedZeroFromTheTransportOverTheWire` and `TestARunWhoseStreamEndedNormallyIsExitedZeroFromTheTransportOverTheWire` (the wire: `start_observed` true, `remote_may_survive` absent, output `UNSPECIFIED`), `TestPodExecEndedNormallyIsTheTransportsWordAndABrokenStreamIsLost` (the illustration), `TestTheGuideTeachesTheDecisionOnASuccessStatusAndTheStartOfAQuietCommand` (the guide no longer says that a `nil` is `Lost`), and conformance cases 16 and 17. What the SDK cannot do is read client-go's status channel (the guide says so, and what an author who owns the WebSocket can do).
- **B1.4, values nobody can deliver: decided; two stay undelivered.** Every other value is now produced and deliverable. `CLOSED_BY_PLUGIN_SHUTDOWN`: the plugin stops, and the end reaches an attached stream before the server stops, because the controller's `Shutdown` is held (for 1.5 s at most) until every attached stream has been sent its `Ended` (`TestTheControllersShutdownEndsEverySessionBeforeTheServerStops`, `TestAStuckAuthorsSessionStillReceivesItsEndBeforeTheServerStops`); a session with no stream ends the same way and its end is the tombstone's (`TestShutdownEndsDetachedSessionsClosedByPluginShutdownAndTombstonesThem`). `CLOSED_BY_DETACH_TIMEOUT`: the lease of a session with no stream, which ends it with no `Ended` frame, so the host reads the end from the tombstone (conformance cases 9 and 11, `TestTheLeaseEndsADetachedSessionClosedByDetachTimeoutAndNobodyIsSentAnEnded`). `CLOSED_BY_RUN_TIMEOUT`: a run that reaches its timeout, which the host reads as the outcome `TIMED_OUT` and not as a `Closed` arm, because a run has no `Ended` (`TestServedRunEndsAtItsTimeoutWithTheOutputSoFar`). `CLOSED_BY_CANCELLED`: a run whose call was cancelled, and a session that the SDK destroyed because its host broke the protocol or never learned that it exists, whose end the host reads from the tombstone (`TestAStreamThatBrokeTheProtocolEndsTheSessionItHoldsOrLeftOnlyBecauseItEndedAndNoOtherStreamHoldsIt`). The two that stay undelivered: `OUTCOME_CANCELLED`, which the engine maps from a run closed by `CANCELLED` (`run_result_test.go`) but which no host receives, because the host that cancelled its call gets the transport's own status and never a result (`TestServedRunThatTheCallerCancelsFreesItsPlace`, `TestCancellingTheCallersContextReachesThePluginAndEndsTheCall`); and `CLOSED_BY_IDLE_TIMEOUT`, which nothing produces and no limit can bound. Both stay reserved: delete them before the tag, or give them a producer.
- **B1.5, redundant fields that can disagree: open.** Neither pair was reduced. The SDK writes `OutputAccount.truncated` as `dropped_bytes != 0`, and `Failed.stage` from the same observation that `start_observed` reports, with one exception that a test pins: the failure the SDK makes of a broken `Exit` (an empty or mixed `Exit`, a signal from a target that reports none) is stage `RUN` even when the start was not observed (`TestWhatTheFunctionReturnsBecomesTheTypedEndOfItsSession`, the case "an empty Exit is never an exit 0"). Nothing rejects a disagreement from another producer: that decoder is B1.6's.
- **B1.6, consumer readers: open.** The readers belong with the first host consumer (H1a-1), and this repository has none: `Client` returns the wire messages as they came, with an absent fact absent and an unknown enum number kept. What the SDK holds is the rule and its checks: the guide's "Absence is unknown", `TestAbsenceIsUnknown`, `TestBlocker1*` to `TestBlocker5*`, and conformance case 28, which compares the presence of `remote_may_survive` and not only its value.
- **B1.7, `OpenRequest.kind`: open.** The `oneof` is unchanged (`OpenRequest` carries `start` and `attach` in `oneof kind`): the wire-identical change to two optional fields, agreed for before any tag, was not made and stays on the list. A request that carries both arms still reaches admission as the later arm alone (B5).
- **B1.8, refusal encoding: decided.** The encoding is the metadata strings of `google.rpc.ErrorInfo` (domain `omniview.sdk.exec.v2`, reason = the class, metadata `reason`, `program`, `selection_name`, `selection_value` and `retry_after_ms`) with a bounded `LocalizedMessage`, which the proto's header states and every refusal uses, the calls added by this change included: `TestTheServedCallsThatManageSessionsAreTypedAndAnswerForTheTombstone`, `TestTheSessionCallsAreStrictAndReadTheSessionContextOfTheCall`, `TestAnAttachToASessionThatDoesNotExistIsNotFoundTypedAndNothingRan`. No typed detail message was added.
- **B1.9, `Session`/`Run` declaration: open.** A target with neither section still registers without an error or a log line and serves only `Options`, `Exec` is still required for it, and the SDK still reads the declaration as "a section of `Info` that is not zero" (`registeredTarget.servesSessions` and `servesRuns`). The guide says so (`docs/exec.md`, "What you write and what the SDK owns").
- **B1.10, ownership and sizes: the calls are served and sized; ownership and the size of a listing are open.** `ListSessions`, `ReadOutput` and `EndSession` are served (`FEATURE_SESSION_MANAGEMENT`): `TestTheServedCallsThatManageSessionsAreTypedAndAnswerForTheTombstone`, `TestEndSessionRefusesASessionWithAStreamAttachedAndKnowsNoUnknownOne`, `TestASessionThatEndsBetweenTheTwoReadsOfAListingIsListedOnceWithItsEnd`, `TestAReadOutputOfASessionThatEndsBetweenItsTwoLookupsIsReadFromTheTombstone`, conformance cases 9, 10 and 25. *Ownership*: none of them, nor an attach, carries a route, and the plugin does not check which connection started a session: a session is named by its id alone. Open. *One bound policy*: a call that starts something refuses a value above its bound (`Start.detach_timeout_ms`, `Start.replay_bytes`, a size, the bounds of a run: `TestAReplayRingAboveTheTargetsMaximumIsRefusedAndNothingRan`), and a frame or a call that asks how much of what exists is clamped, and says what it applied (`Detach.lease_ms`, `ReadOutput.max_bytes`: `TestTheLeaseOfADetachIsWhatTheHostAskedForTheSessionsOwnOrTheMaximumAndTheSessionEndsExactlyThen`, `TestReadOutputIsClampedToTheRingAndStartsAtItsFront`). Decided. *Sizes*: an `Output` frame is at most 64 KiB, a chunk of the ring is 64 KiB (smaller for a ring under 256 KiB), a `ReadOutput` answers at most 1 MiB in at most 1024 chunks and 64 KiB when `max_bytes` is zero (`TestReadOutputIsACursorReadOfTheRingAndHoldsToItsBounds`), and the tombstones hold at most 256 sessions and 32 MiB of output (`TestTheStoreKeeps256TombstonesAndDropsTheOldestFirstWithTheirIds`, `TestTheStoreKeeps32MiBOfOutputAndTheOldestLoseTheirBytesAndKeepTheirEndAndId`). A `ListSessions` answer has no bound of its own: it lists every live session (at most each target's `MaxSessions`) and every tombstone in one message. Open.
- **B1.11, `Exit` default: open.** `SourceUnspecified` beside a code or a signal is still read as `PROCESS` (the documentation of `Exit.Source` says so), and `Exit` still has exported fields. `ExitCode(...)` is the constructor the guide teaches, and an `ExitCode` from a target whose `ExitReport` is `ExitReportNone` is downgraded to `TRANSPORT` with a violation (conformance case 17).
- **B1.12, vocabularies and the string guard: open.** `Choice.Kind`, `Choice.Detail` and the states are still the provider's to invent (K1a). `TestAbsenceIsUnknown` still audits bool, numeric and bytes fields and not strings; `Choice.no_program` is in its audit as a declared bool. The presence rules of `Mark` have no producer to hold them, because the SDK serves no marks.
- **B2, names that still collide: open.** The Go prefixes of `enums_v2.go`, `SessionFacts`, `Capabilities`, `TargetRef` and `exec.Request` are as the review found them. This change adds three more names that the wire also has with another shape: `exec.Fact`, `exec.Query` and `exec.Foreground`, beside the wire's `Fact`, `Query` and `Foreground`. **Found and not closed.**

- The resource lane has no hook for the retirement of a connection, so the options cache drops a connection's answers when a command or an `Options` call sees the retirement, and otherwise an answer lives out its 5 s. Concurrent starts of a cold request may each run the callback once (no single flight).
- An error that carries its status only in text (client-go's upgrade) is not typed by the SDK: the author's `Classify` does it with `ErrorFromHTTPStatus`.
- The container and mode combination cannot be said by per-choice capabilities: a container without stdin accepts an attach that asks for it and the input goes nowhere (proof 5.13), and the exit code of an attach is in the Pod status, which only a provider can read.
- Not served by the SDK and needed by the same provider: `Classify` has no request (proof 5.8), `LinkHealth` cannot be implemented over client-go (5.11), the wait for an ephemeral container that is starting has no place in the contract (5.5), and the vocabularies of `Choice.Kind` and `Choice.Detail` are the provider's to invent (5.6, B1.12).
- A `Close` or a kill that follows input which the function never reads waits behind it, because the frames of a stream are applied in the order they were sent. The way out is to cancel the stream and end the session with `EndSession` and a kill (`TestACloseFrameBehindInputTheFunctionDoesNotReadWaitsAndCancellingTheStreamDetachesAndEndSessionEndsTheSession`).
